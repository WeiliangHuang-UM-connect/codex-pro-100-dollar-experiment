# CSV 订单多表合并与核对：可运行作品样例

这是一个用于展示交付方式的小型演示。`samples/` 中的姓名、订单和金额全部为人工合成数据，**不是实际客户数据，不代表客户项目、成交记录或收入**。程序仅读取命令中明确指定的输入文件；不会扫描用户目录、联网或上传数据。

## 运行

需要 Python 3.10 或以上，只使用标准库，不需要安装第三方依赖。在 PowerShell 中执行：

```powershell
Set-Location 'examples/csv-orders'
python merge_orders.py --input samples/orders_a.csv samples/orders_b.csv --output output
python -m unittest -v
Start-Process .\output\report.html
```

演示包含两个输入文件、13 条记录。预期输出：有效唯一订单 4 条，待核对 9 条，3 个重复ID组（其中 2 组内容冲突），2 条金额非法记录。演示特意包含前导零订单ID、中文字段值、相同重复、金额冲突、空字段和大金额。

## 交付文件

| 文件 | 内容 |
| --- | --- |
| `output/clean.csv` | 字段有效且订单ID唯一的记录，金额统一为两位小数，附来源文件和行号 |
| `output/review.csv` | 所有异常与重复行；附原因、重复组大小、原始金额和完整原始字段 JSON |
| `output/summary.json` | 行数、异常统计，以及可解析金额的核对数据；金额以字符串存储 |
| `output/report.html` | 可离线打开的中文核对报告，展示清洗结果、异常记录及金额等式 |

样例金额核对为：`1000000000081.81 = 1000000000012.41 + 69.40`，分别对应可解析输入金额、有效唯一订单金额、待核对行中的可解析金额。金额非法的行不参与求和。**重复行仍计入输入和待核对金额，因此该等式不是去重后的营业额。**

## 处理规则

- 输入是 UTF-8（可带 BOM）CSV；表头必须恰好为 `订单ID,客户,金额`，列顺序可变化。输出 CSV 使用 UTF-8 BOM。
- 订单ID始终按文本处理，保留 `0001` 等前导零；字段两端空白会清除。ID和客户不能为空。
- 金额使用 `Decimal` 精确解析、求和，不经过浮点数。只接受非负普通十进制、最多 16 位整数和 2 位小数；不接受货币符号、千位分隔符、负数、科学计数法和 `NaN`。
- 同一ID出现多次时，**整组所有行都进入待核对文件**，不会自动选一条，也不会静默丢弃冲突行。数值相等的 `8.0` 与 `8.00` 视为相同金额。无效金额与有效金额出现在同一ID下也按冲突保留。
- 列数异常的记录进入待核对文件，原始字段仍保留。来源行号从 1 开始且包含表头；支持引号内换行，另存结束行号。完全空白行由CSV解析器跳过，不计入记录数。
- 读取完全部输入后才生成结果；坏表头、无法解析的CSV语法或编码会直接报错。原始输入以只读方式打开；输入与输出文件重名重合时拒绝运行。重复传入同一文件也会报错。

## 支持边界

适合少量、同一币种、统一三列表头的本地订单导出；所有数据在内存中处理。演示不处理 XLSX、多币种汇率、退款负数、日期、税费、自动纠错、模糊客户匹配或业务账务结论。更复杂规则需要先明确，再修改程序。

用 Excel 查看 CSV 时，请通过“数据 → 从文本/CSV”导入，并将订单ID列指定为文本，避免 Excel 自行移除前导零。该演示不会改写文本来防止电子表格公式执行；外部来源的文本应按文本导入。报告对所有字段做 HTML 转义。

同一输出目录再次运行会覆盖这四个生成文件；运行报错后，目录中可能仍有上一次结果，不应把旧结果当作本次成功输出。程序不自动修改或删除输入文件。

## 验证内容

四个 `unittest` 测试验证：冲突和相同重复整组保留、精确金额核对、前导零保留、原始输入 SHA-256 不变、非法金额拒绝、列数异常保留、跨行字段来源行号以及输入/输出重合保护。所有测试只使用随附或临时生成的合成数据。
